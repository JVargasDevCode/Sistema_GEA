# 5. Escopo

O escopo do GEA define as funcionalidades que serão desenvolvidas na primeira versão do sistema, assim como os recursos que não fazem parte desta etapa.

## 5.1 Funcionalidades incluídas na primeira versão (v1)

A primeira versão do GEA contará com as seguintes funcionalidades:

### Cadastro e gerenciamento

* Cadastro de eventos acadêmicos.
* Cadastro de atividades.
* Cadastro de palestrantes.
* Associação de palestrantes às atividades.

### Inscrições

* Inscrição on-line dos participantes.
* Consulta das atividades disponíveis.
* Controle automático da quantidade de vagas.
* Bloqueio de novas inscrições quando uma atividade atingir sua capacidade máxima.
* Acompanhamento das inscrições realizadas pelo participante.

### Controle de presença

* Registro da presença dos participantes.
* Consulta da presença por atividade.
* Cálculo da frequência dos participantes.

### Certificados

* Verificação automática da frequência mínima exigida.
* Emissão automática dos certificados para participantes aptos.
* Disponibilização dos certificados para os participantes.

### Avaliações

* Avaliação das atividades pelos participantes.
* Armazenamento das avaliações realizadas.
* Consulta das avaliações pelos organizadores.

### Relatórios

* Relatório de inscrições.
* Relatório de presença.
* Relatório de frequência.
* Relatório de avaliações.
* Dados consolidados para auxiliar os organizadores na análise dos eventos.

## 5.2 Funcionalidades não incluídas nesta etapa

Para manter o projeto dentro do prazo e do escopo definido para a primeira versão, os seguintes recursos não serão desenvolvidos:

* Sistema de cobrança ou pagamento de inscrições.
* Integração com sistemas acadêmicos institucionais, como sistemas de matrícula.
* Aplicativo móvel nativo para Android ou iOS.
* Emissão de certificados com validação por QR Code ou blockchain.
* Envio de notificações por SMS.
* Envio de notificações por WhatsApp.
* Integrações com gateways de pagamento.

O sistema será disponibilizado exclusivamente por meio de um navegador web, porém contará com layout responsivo para permitir sua utilização em computadores, tablets e dispositivos móveis.

## 5.3 Restrições

O desenvolvimento do projeto estará sujeito às seguintes restrições:

* O projeto deverá respeitar o cronograma estabelecido para o primeiro bimestre da disciplina.
* Serão utilizadas tecnologias web já conhecidas pelos integrantes da equipe.
* O acesso ao sistema será realizado exclusivamente por navegador.
* Não será desenvolvida uma versão desktop instalável.
* Não haverá, nesta etapa, orçamento destinado à contratação de serviços pagos de envio de mensagens ou gateways de pagamento.
* Funcionalidades que dependam de integrações externas poderão ser consideradas em versões futuras do sistema.
